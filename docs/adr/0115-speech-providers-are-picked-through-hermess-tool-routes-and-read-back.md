# Speech providers are picked through Hermes's own tool routes, keys are write-only, and every save is read back

Issue #168 asks for a Voice section in Settings that picks the speech-to-text and text-to-speech provider for Dictation, Read aloud and Voice conversations (ADR 0111). It should list the providers Hermes supports, show which are set up, and edit the picked provider's model, voice, language and API key. Until now the app only showed the provider names, which Rust read from the profile's config (`Dashboard::voice_setup`).

## What the server offers (checked in source at the deployed `f0d94882e8`, v0.22.6)

The official `hermes tools` picker and the desktop app use these dashboard routes in `hermes_cli/web_routers/tools.py` and `config_env.py`. All of them take `?profile=`.

- **`GET /api/tools/toolsets/{stt,tts}/config`** lists the providers Hermes offers: `TOOL_CATEGORIES` in `hermes_cli/tools_config.py`, plus plugin text-to-speech rows. Each row has its `name`, `badge` and `tag`, its env vars with `is_set` (never a value), `is_active`, and `status` from `provider_readiness_status`: `ready`, `needs_keys`, `needs_setup` (a local install such as faster-whisper or Piper) or `needs_auth` (Nous Portal or xAI sign-in). Text-to-speech rows also name their `tts_provider`. Speech-to-text rows don't name theirs, so the app maps them from the names `TOOL_CATEGORIES` gives them at this checkout.
- **`PUT /api/tools/toolsets/{stt,tts}/provider`** `{provider}` picks a row by name. It runs `apply_provider_selection` under the config lock, which writes `<kind>.provider` (or `nous` for the Nous Subscription row) and drops a legacy `use_gateway`. It doesn't install anything, prompt for anything, or touch keys. An unknown name is a 400 before anything is written.
- **`PUT /api/tools/toolsets/{stt,tts}/env`** `{env: {NAME: value}}` saves keys to the profile's `.env`. It takes only env vars that the toolset's providers list, and skips a blank value.
- **`PUT /api/config`** `{config}` deep-merges over the stored config under the config lock. This app already relays it for Settings → Model. A provider's model, voice and language live in `stt.<provider>.*` and `tts.<provider>.*`. `GET /api/config/schema` gives the fixed choices for some of them, such as `stt.<provider>.model` from `STT_MODEL_CATALOG`.
- **`POST /api/tools/toolsets/{name}/post-setup`** runs a provider's install as a background `hermes tools post-setup` on the server.
- Hermes reads the speech config on every call: `_load_tts_config()` in `text_to_speech_tool`, and `_load_stt_config()` in `tools/transcription_tools.py`. The audio routes run inside the profile's config scope. So the next recording or reply uses a change, with no restart.

There is no revision or ETag on any of these, and nothing lists command or plugin speech-to-text providers as rows.

## Decisions

- **Settings gets a Voice tab.** It holds the Voice section that was in General: whether Dictation, Read aloud and Voice conversations can be used, and how a turn ends. Below it is **Speech providers**, with one block for speech-to-text and one for text-to-speech. Each block has a picker of the rows Hermes lists, each row marked In use and with its readiness (Set up, Needs a key, Not installed, Needs sign-in). Under the picker is the picked provider's state, its key fields and its settings. The tab is searched in place, like Model and Toolsets (ADR 0047). General's "Voice & screenshots" group (`0113-settings-tabs-keep-their-strip-and-gain-a-sub-nav.md`) loses its voice rows to this tab and becomes "Screenshots". The speech providers are tall, and putting them in that group would bring back the scrolling the sub-nav removed. Whether a ninth tab is right is for the owner, who chose the tab strip, to confirm.
- **Which settings are shown.** These are a fixed list per provider, by Hermes's own config keys (`PROVIDER_FIELDS` in `voiceSettings.ts`): model, voice or voice ID, and language, plus `stt.language`, the hint for every speech-to-text provider. Where the schema has a fixed list, the field is a select. Otherwise it is text. Other settings, and providers the list doesn't know, keep what the config has. The Nous Subscription rows show no settings, because Hermes's gateway picks them.
- **Rust passes only those settings.** `voice_setup` adds `sttLanguage`, `sttSettings` and `ttsSettings`. These hold only `model`, `model_id`, `voice`, `voice_id`, `language` and `language_code` (`VOICE_SETTING_KEYS`) of each provider section, only as text of at most 256 characters with no control characters, and never anything under `providers` (command providers). A value is passed unchanged or not at all, so a check later compares like with like. This screen never reads the config in the webview: `stt.openai.api_key` and the like sit in it. (Settings → Model already reads `GET /api/config` in the webview, unfiltered, which was true before this change. Closing that is a separate fix.)
- **What isn't sent.** A blank is refused where Hermes would use it. Hermes reads most voice settings as `cfg.get("voice", DEFAULT)`, so a blank written there is used as the value, and `PUT /api/config` can't remove a key. These may be blank: language fields, the speech-to-text models Hermes falls back on (Local Whisper's, xAI's and DeepInfra's), and the text-to-speech settings Hermes falls back on (xAI's and Mistral's voice ID, Gemini's model and voice, Piper's voice, DeepInfra's model). Groq, OpenAI and Mistral send a blank model as it is, so theirs may not be blank. A value of spaces alone is never sent, because some providers strip before falling back and others don't. A setting longer than 256 characters is refused too, since it could never read back. A provider whose readiness is `needs_auth` can't be picked: Hermes's route writes a Nous Subscription pick as `nous` before it says the account isn't entitled (`needs_nous_auth`), which leaves no provider in use. The screen says why and keeps Save off. Picking another provider on a side drops the key and settings typed for the last one, so nothing hidden is sent.
- **Naming Local Whisper.** With `stt.provider` unset, Hermes's list marks Local Whisper in use (`_ACTIVE_CHECKS` reads a missing provider as `local`), but at run time it picks: Local Whisper if installed, else the first cloud provider with a key. So the picker then reads "Picked by Hermes (now Local Whisper)", and picking Local Whisper is a change that writes `stt.provider: local`.
- **Keys are write-only.** Hermes says only whether each one is set. A typed key goes out once through the `env` route, and the field is emptied after any save attempt. It isn't kept in a draft, on disk, or in a log. A blank key isn't sent.
- **Relay.** Rust relays only `PUT api/tools/toolsets/{stt,tts}/provider` with exactly `{"provider": text}`, and `PUT api/tools/toolsets/{stt,tts}/env` with exactly `{"env": {NAME: text}}` (`voice_provider_write`). The provider name is not blank, at most 200 characters and has no control characters. The env object is never empty. Each name is an env var name (`[A-Z][A-Z0-9_]*`, at most 128 characters). Each value is not blank, at most 4096 characters, and has no control characters, so it can't add a `.env` line. Other toolsets' `provider` and `env` routes, and every `model` and `post-setup` route, are still refused (ADR 0021).
- **Checked first, read back after (as ADR 0021 and 0045).** A save is one queue for the whole app. Inside it, the providers and settings are read again first. If the provider on a side the owner changed differs from what the owner saw, nothing is sent and the screen says what changed. That covers both the row Hermes marks in use and the name the config writes, so a switch between two command providers Hermes doesn't list is caught too. The same goes for any setting the owner changed. A typed key is emptied after any attempt, one that fails before Hermes answers included. A save also drops any read still on its way from before it, so an older read can't undo what the save read back. A conflict, or a Read again that finds Hermes changed something the owner had edited, drops those edits. A side counts as changed when the draft picks there or holds a key or a provider's setting there, since those were typed for the provider shown then. Such a side loses everything typed for its old pick, so nothing the owner no longer sees is sent. The screen then names what changed and shows Hermes's values. A pick is confirmed only when the config names the same provider as the row marked in use (its section, or `nous` for a Nous Subscription row). Hermes marks Local Whisper in use even while `stt.provider` is unset, and the list and the config are separate reads that could disagree. If Rust couldn't read the profile's config, the screen doesn't offer to save, since nothing could be checked or confirmed. Otherwise keys go first, then the picks, then one `PUT /api/config` with only the changed settings. Then everything is read again. It is called saved only when the read shows the picked providers in use, the settings as sent, and each sent key set. A key whose write didn't answer is never called saved, even when the read shows it set, because Hermes may still hold the key it had before. A 4xx stops the save, and the screen says what Hermes had already taken. A lost answer or a 5xx is decided by the read: it is "saved", with the error noted, when the read shows everything, and otherwise "may have been saved, or may yet be".
- **Late answers.** Every read and save names its profile. The screen numbers its reads and drops any answer that isn't the latest for the profile and connection shown. A save that finishes after a profile switch tells nothing to the new profile's screen. A panel that opens while a save for its profile is still on its way (Settings left and opened again) shows it saving, takes no edits, and reads Hermes again once the save lands. A switch also drops the draft and any typed key.
- **The chat panes follow.** A save (and a Toolsets switch of speech-to-text) drops the connection's cached voice set-up and tells the panes. Dictation, Read aloud and a running Voice conversation then name the new providers.
- **Reachable from the conversation.** The Voice conversation panel says which providers it uses and has **Change voice settings**, which opens Settings → Voice. Settings covers the pane, so the conversation pauses there, as ADR 0111 says, and only the owner resumes it.
- **A server without the routes.** If `GET …/stt/config` answers FastAPI's own 404 or 405, or `has_category: false`, the section says the server can't list its speech providers, and says to use `hermes tools` on the server. The Voice section above still shows the providers the profile names.

## Considered options

- **Write `stt.provider` and `tts.provider` with `PUT /api/config`.** Rejected. That skips `apply_provider_selection`, which writes `nous` for a managed row and drops `use_gateway`. The picker would also need a provider list the app keeps itself.
- **Save keys with `PUT /api/env`** (Setup's Provider key route). Rejected. That route takes any env var, and Rust allows it only for model providers' keys after the provider checks them. The toolset `env` route takes only what the voice providers list.
- **Read settings from `GET /api/config` in the webview.** Rejected for this screen. The answer is unredacted. Rust already reads it for the voice set-up and can pass on just the six setting keys.
- **Install local providers from here** (`post-setup`). Not now. It runs installs on the server in the background, behind a status poll this app doesn't have. The screen says "Not installed" and points to `hermes tools` on the server. This could follow ADR 0045's confirm-then-run pattern later.
- **Guard leaving with an unsaved change**, as Memory and Skills do. Not done. Like Settings → Model, a change lives while the tab is open. A typed key isn't kept anyway.

## Consequences

- The owner can pick, configure and give keys to the speech providers of the profile shown, from Settings or from a Voice conversation. Each save is confirmed by Hermes's own read.
- With no revision on the server, a change made elsewhere between the check and the write can still be overwritten. The window is one round trip, and the check narrows it.
- Values Rust doesn't pass on (not text, too long, or with control characters) aren't shown, so a change to them by another client isn't caught as a conflict.
- The speech-to-text names (`STT_SECTION`) and `PROVIDER_FIELDS` follow `f0d94882e8`. A provider Hermes adds or renames later is still listed and can be picked, but its settings stay on the server until those maps learn it.
- Not verified against a real Hermes: the routes were read in source at `f0d94882e8` and exercised against the fake dashboard (`fakeVoiceProviders.ts`), which follows that source. See the pull request for what was run.
