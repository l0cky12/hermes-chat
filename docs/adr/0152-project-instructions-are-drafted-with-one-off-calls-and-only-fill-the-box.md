# Project instructions are drafted with one-off calls, and a draft only fills the box

Issue #536: the project's **Instructions** box (Defaults for new chats, ADR 0017) gets a button that has Hermes write them. With text in the box it reads **Improve with AI**: Hermes rewrites the text. With the box empty it reads **Write with AI**, and the owner picks one of two ways to start: write notes about the project in one box, or let Hermes ask questions one at a time. Every way ends in the same review: **Use this**, **Ask again** with an optional note, or **Cancel**.

## Decisions

- **Every call is legacy `llm.oneshot`**, the stateless model call that Artifacts' Ask Hermes to edit already uses (ADR 0029): `{profile, instructions, input, max_tokens, temperature}`, with no `session_id`. It has no tools, starts no chat, and writes nothing to any chat's history. The question flow is a series of these calls. Each one carries every question asked so far, with its answer or a mark that it was skipped, and gets back the next question or `READY`. After 8 questions, or at `READY`, or when the owner presses **Write it now**, one more call writes the draft from the answers. **Ask again** sends the same material with the previous draft, which the new one must differ from, and the owner's note.
- **What Hermes is given.** The project's name and folder paths, then the owner's material between tags (`<instructions>`, `<notes>`, `<answers>`), which the call is told is data, not instructions to it. The prompts are in `src/hermes/instructionsAI.ts`. Notes are capped at the box's own limit (20,000 characters), one answer at 4,000, and a draft at 4,096 tokens.
- **Which model writes.** `llm.oneshot` can't be given a model. It accepts only `session_id`, `profile`, `template`, `instructions`, `input`, `variables`, `task`, `temperature` and `max_tokens`, and the shared gateway refuses any other field as `invalid_params` (`gateway/session_llm_oneshot.py` `_FIELDS` at v0.22.6). Only a live session can lend its model, and borrowing one would mean starting a chat. So a draft is always written by the profile's Text generation model (`auxiliary.title_generation`, or the main model when that task is on `auto`), never by the project's default model. The dialog says so and names that model, read from `GET /api/model/auxiliary`.
- **Nothing is saved.** **Use this** puts the draft in the box as an ordinary edit. The form then shows "Unsaved changes", and its **Save defaults** and **Cancel** decide, with the revision check of ADR 0017. Cancelling the dialog, a failed call or **Stop** leaves the box as it was.
- **A draft goes only into the text it was written for.** The review keeps the box's text from when the draft was asked for. If the box changed meanwhile (the form shows a save made in another window when it has no edits of its own), **Use this** is refused and **Ask again** works from the box as it is now.
- **Failures keep everything.** A failed or timed-out call (the app waits 90 s, as ADR 0029 does) shows Hermes's reason in the dialog. The notes, the answers so far and the answer being typed stay there to try again. A missing sign-in for the Text generation model's provider reads as it does for Regenerate title. A dropped connection fails the next call and leaves the dialog open. The button can't be pressed while Hermes isn't connected.
- **Stop.** Hermes has no way to cancel an `llm.oneshot` it has started, so **Stop** drops the answer when it comes and gives the dialog back at once. The call still runs to its end on the server.

## Considered options

- **Run the questions in a hidden chat.** Rejected: it would create a session, show up in other clients' history, and give the model tools.
- **Lend the project's model through a session.** Rejected for the same reason. Backend gap: `llm.oneshot` taking `provider` and `model` would let the project's default model write its own instructions.
- **Save the draft at once.** Rejected: the issue asks that only Save defaults decides what's kept.
