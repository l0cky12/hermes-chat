# Speech to text can run on this computer, with an engine already installed, and Rust alone decides where a recording goes

Issue #220, the first slice of #192, asks that Dictation and Voice conversations (ADR 0111) can turn speech into text with an engine already installed on the computer running the app, with nothing to download, instead of on the Hermes server. ADR 0111 rejected local speech-to-text because #90 ruled out desktop-local substitutes; #220 asks for it as an owner's choice, so this ADR supersedes that one rejected option and nothing else of 0111.

## Decisions

- **Where it runs is one choice for this computer.** Settings → Voice → Speech to text has "Where it runs": Hermes server (as before, the profile's speech provider, ADR 0115) or This computer. It is kept by Rust in `local-stt.json` in the app's config folder, for every connection and profile, and so survives a restart. A file that can't be read is an error, not "Hermes server": that default would send audio the owner said must stay here.
- **Rust decides, inside the one transcribe command.** `hermes_transcribe`, which Dictation, the Voice conversation loop and the Test button all call, first reads the choice (`local_stt::transcribe_if_local`). With This computer chosen, the recording goes to the local engine and never to Hermes, even when the engine can't run: then it fails and says why. The webview can't send a recording to the server by mistake, and there is no fallback to the server here; that is #192's option.
- **Engines found.** On `PATH`, by name: `whisper-cli` and `whisper-cpp` (whisper.cpp), `whisper` (whisper.cpp's old binary, or OpenAI Whisper when it is a `#!` script), `whisper-ctranslate2` (faster-whisper's command line) and `vosk-transcriber`. Models in their usual folders: `ggml-*.bin` in `whisper*` folders (and their `models`) under the XDG data folder, `/usr/share` and `/usr/local/share`, plus `~/.cache/whisper.cpp` and `~/whisper.cpp/models`; `*.pt` in `~/.cache/whisper`; Hugging Face snapshots of `*whisper*` repositories holding `model.bin`; Vosk folders holding `am/` in `~/.cache/vosk`, the data folder's `vosk` and `/usr/share/vosk`. Each found program's `--version` line is shown when it answers within 5 s. faster-whisper as a Python library alone has no command line, so it isn't found; the how-to names `whisper-ctranslate2`.
- **The webview names nothing to run.** It picks an engine and model only from what Rust found on this read (`local_stt_set` checks them against a fresh scan, and takes the engine's kind from the scan, not from the webview), or keeps what is already chosen. A program or model elsewhere is picked in the native Open dialog that Rust opens (`local_stt_pick_program`, `local_stt_pick_model`); a program must have one of the names above and be executable.
- **How it runs.** A fixed argument list per engine (`local_stt::args`), never a shell. The WAV the app already records (16 kHz mono) is written to a new private folder (mode 0700, created with `create`, so nothing already there is followed) as `audio.wav` (0600), the engine writes `audio.txt` beside it, and the folder is deleted whatever happens. Engines run with `HF_HUB_OFFLINE=1`, so faster-whisper can't fetch a model, and are killed after a minute plus three times the recording's length. A failure says which engine, its exit code and the last line it printed. whisper.cpp's `[BLANK_AUDIO]` and other bracket-only lines are dropped.
- **The rest of the app follows.** The chat panes' voice set-up gains `sttLocal` (the engine's name, or why it can't run). With it, Dictation and Voice conversations no longer need the server's transcription route or `stt.enabled`, and they name the local engine. They still need Hermes connected, to send the text. A change in Settings tells the panes, as a speech-provider save does.
- **Test.** Records five seconds, sends them through the same command Dictation uses, and shows the text, the time the transcription took and which engine or provider answered, or why it failed.

## Considered options

- **Keep the choice in the webview's storage and pass the program to Rust.** Rejected: the webview would name a program to run, which #220 forbids, and a lost choice would quietly send audio to Hermes.
- **A separate `local_stt_transcribe` command, chosen by the webview.** Rejected for the same reason: a webview bug could still reach the server path. One command that decides in Rust is the guarantee the setting promises.
- **Run faster-whisper through `python3 -c`.** Not now. It needs a script of our own and a Python environment guess; `whisper-ctranslate2` is its packaged command line.
- **Parse each engine's stdout.** Rejected: each prints progress and timestamps differently. All four write a plain `.txt` file when asked.

## Consequences

- With This computer chosen, audio never leaves this computer; only the text goes to Hermes, when the owner sends it.
- Tested against a real whisper.cpp 1.9.5 (`whisper-cli`, `ggml-tiny.en.bin`, its `jfk.wav` sample) through `local_stt::transcribe` (`cargo test -- --ignored real_whisper_cpp`). faster-whisper, OpenAI Whisper and Vosk weren't installed on the build machine: their argument lists follow their documented command lines and are unit-tested, not run.
- No microphone on the build machine, so the Test button was exercised in tests with a stand-in microphone, not live.
- ADR 0065 (#192) builds on this one: either side can be the backup for the other, decided by Rust in the same command, and Whisper models can be downloaded for whisper.cpp. With This computer and no backup, this ADR's guarantee is unchanged. The real-engine test is now `real_whisper_cpp`, run when `HERMES_TEST_WHISPER_CLI`, `HERMES_TEST_WHISPER_MODEL` and `HERMES_TEST_WHISPER_WAV` are set.
