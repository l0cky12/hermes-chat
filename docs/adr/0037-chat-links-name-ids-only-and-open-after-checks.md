# Chat links name ids only, and open a chat only after every check passes

Issue #79 asks for a link that opens one chat in the right connection and profile, from a cold start or into the window already open, with a pending state that never sends anything, and clear messages when the chat, profile or connection is gone.

A link is `hermes-chat://chat?v=1&connection=<ref>&profile=<profile>&id=<chat id>`.

## Decisions

- **The connection is an opaque reference made on this computer.** The first Copy chat link for a connection makes 20 random characters (100 bits) and keeps them in local storage (`hermes-chat.connection-refs`), mapped to the connection's mode, SSH target or URL, and username: the same identity inbox dismissals use. Nothing about the server can be read from the reference, and the link never carries an address, username, password, header, token or command. A link opens the chat only on the computer that made it, unless the owner maps it (below).
- **Main has one saved sign-in, so the reference is mapped to that identity, not to a saved-connection id.** PR #125 (saved connections with stable ids) is open. If it merges, its stable id can replace the identity the reference maps to, and references already copied can be carried over by mapping each one to the connection whose old scope it names.
- **Strict reading.** The window reads a link with the URL parser only after checking that it is at most 1,024 printable ASCII characters. The scheme must be `hermes-chat`, the host `chat`, with no path, port, fragment, username or password. There must be exactly the four parts, each once, and `v` must be `1`. A newer version asks the owner to update. After decoding, the profile must be a Hermes profile id (`[a-z0-9][a-z0-9_-]{0,63}`, or `default`), the chat id letters, digits and `_ . : -`, starting with a letter or digit, at most 128 characters, and the reference 8 to 64 characters of `[A-Za-z0-9_-]`. So no id can hold `/`, `%` or `..` as a path segment, however the link was encoded. Rust only picks out arguments that start with the scheme and are at most 1,024 bytes; the window does the reading, in one place with its tests.
- **Every check before anything moves.** In order: the link's connection is the one signed in, Hermes is connected, `GET /api/profiles` lists the profile, and `GET /api/sessions/{id}?profile=` has the chat. Only then does the app switch profile and open the chat. A failure changes nothing on screen, so the chat and its draft stay, and a notice says what is wrong and what to do: try again, open Setup, or dismiss. A deleted chat answers 404, which reads as gone. Any other failure offers Try again.
- **The profile switch is the switcher's.** A link to another profile switches the way the switcher does. With a reply running or an Approval waiting, the notice asks first, using the switcher's own words. An unsaved persona, memory or skill edit asks as leaving Settings does. The chat opens once the new profile's list has been read. The owner going to a third profile meanwhile drops the link.
- **Links only navigate.** Nothing a link holds is sent to Hermes except the profile and chat id in those two GET requests. A link never sends a message, runs a command or tool, answers an Approval, or signs in. While it waits, the notice says that nothing is sent, and it never takes focus from the composer. Cancel drops it, and an answer that arrives after Cancel, or after a newer link, is ignored.
- **An unknown connection is never assumed.** A reference this computer doesn't know, such as one from another computer, is refused with an explanation. **Open it here** is the owner saying that the reference is the connection signed in now; it is then kept as an alias (at most 50). A reference this computer knows for another connection points to Setup. The app never dials anything for a link: it has no address to dial, and it never sends one connection's secrets to another.
- **One window, over the existing session bus name.** The desktop runs `hermes-chat <link>` (`%u` in the launcher, which declares `MimeType=x-scheme-handler/hermes-chat`). A link is one more request on `net.l0cky12.HermesChat`, the name the screenshot and global shortcuts use (ADR 0107, global shortcut): the new process claims the name, atomically, or, if a Hermes Chat already has it, calls `OpenLink` with the link and the desktop's activation token, and exits. The running app keeps the link, emits `chat-link`, and brings its window forward as `--show` does. Rust passes on only what could be a link (the scheme, at most 1,024 bytes). With no Hermes Chat running, the process starts with the link and keeps it until the window takes it (`chat_link_take`). The newest link replaces one not yet taken. The window takes links once for the whole app, so a component mounted twice can't lose one. At the sign-in screen, the link waits for sign-in. On a cold start with a link, the last open chat isn't reopened first.

## Considered options

- **`tauri-plugin-deep-link` with `tauri-plugin-single-instance`.** On Linux the deep-link plugin reads the link from the command line, and registers the scheme at run time only for builds without a packaged launcher. The app already keeps to one instance over its own session bus name, which the global shortcut's `--show` and `--toggle` use, so `OpenLink` is another request on that path, with the same atomic claim and activation token, and needs no new dependencies. Registration belongs in the package's launcher, where pacman removes it with the package.
- **The connection's address in the link, or a hash of it.** A link pasted elsewhere would then show, or let someone confirm a guess of, the server's address and username. A random reference shows nothing.
- **Asking Hermes whether the chat exists only after switching.** A chat deleted from a profile would leave the owner switched away from the chat and draft they were in.

## Consequences and gaps

- A link copied on one computer doesn't open on another until the owner maps it with Open it here. Clearing the app's local storage forgets the references, so links copied earlier read as unknown.
- With one connection at a time, a link for another known connection can't switch to it; the owner connects in Setup and opens the link again.
- `GET /api/sessions/{id}?profile=` and `GET /api/profiles` were checked against Hermes at `bf0203a` and the tests' fake Hermes. A Hermes without them can't open links: the lookup fails and the notice says why.
- The launcher's registration is only as good as the desktop's handler list. Browsers and desktops each decide whether to ask before handing a link to an app.
