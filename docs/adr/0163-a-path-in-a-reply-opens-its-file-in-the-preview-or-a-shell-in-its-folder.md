# A path in a reply opens its file in the Preview or a shell in its folder

The owner asked that files, folders and links in a Hermes reply always be clickable. A file opens in the Side panel's Preview, a folder opens the Terminal with a shell in that folder, and a link opens in the Preview as before. "Always" includes a bare path in running text, not only a Markdown link.

Three facts shaped the design. A path is not a URL: react-markdown empties `file:` addresses, and a relative address opened nowhere. The words alone can't say file or folder (`src/ui` has no slash at its end), and only the server knows. And a path is model output, while the Terminal is the owner's own shell (ADR 0022), so anything that puts path text into that shell is a way for a hostile page Hermes read to run a command.

## Decisions

- **A path link is never an address.** A rehype plugin (`markdownPipeline.ts` `rehypePaths`) wraps each path in `<a data-path>` with no `href`, and turns a Markdown link whose address is a path (no scheme, or `file:` on no host) into the same element. Nothing can send the app's window to it, and react-markdown's URL policy for real links is untouched. Code blocks, math and the words of an existing link are left as they are. The plugin runs after highlighting and before find marks, in both plugin lists.
- **Which words are a path is one pure grammar** (`paths.ts` `findPaths`). In running text a path has a slash and enough else to be told from prose: `/usr/bin/env`, `/tmp/`, `/README.md`, `~/notes`, `./run.sh`, `src/ui/Markdown.tsx`, `docs/adr/`. So `and/or`, `1/2`, `TCP/IP`, `origin/main`, `application/json`, a slash command such as `/help`, a scoped package, a glob, and a web address without its scheme (`github.com/a/b`) stay text. A code span that is one path links by a looser rule, since the writer marked it as a name: any `/x`, any relative path whose first segment has two or more characters, a file name the Preview knows, such as `package.json`, and a full path with spaces in its names that ends in a file's extension or a `/` (`/home/liam/My Documents/report.md`; a word after a space that starts with `-` makes it a command). A word that runs on into Markdown's emphasis (`src/__init__.py` renders `src/`, a bold `init`, then `.py`) is only part of a path, so it doesn't link. Trailing punctuation and unbalanced brackets stay out of the link. A line suffix (`:12`, `:12:3`, `#L12`) stays in the link's words and out of the path.
- **Rendering asks the server nothing.** Detection is a function of one text node, so a streamed reply renders the HTML the one-piece render does (ADR 0068), a Saved copy links offline, and no reply makes the server touch a path until the owner clicks. The scan is one pass over each text node, and a word over 1,024 characters is never a path (ADR 0139).
- **A relative path joins the chat's working folder.** `Chat.folder` is Hermes's `cwd` for the session, from the chat list's row, a new or resumed session's `info`, and `session.cwd.set`. `PathLink` resolves at render time against the folder its `PathsIn` names. With no folder, a relative path stays text. `.` and doubled slashes are folded away, and `..` is kept as written, since through a symbolic link only the server knows where it leads (`/bin/..` can be `/usr`). `Chat.folder` is kept in the chat list saved on this computer, so a relative path still links while offline.
- **Paths link only where the text speaks of the server.** `PathsIn` marks a chat's transcript and a Server file in the Preview, whose relative paths join the folder the file is in. Markdown elsewhere (a Local file, a file on the dashboard's machine, Settings) links no path: its `~/notes` is not where Hermes's tools run.
- **A click asks the server once what is there.** `GET api/fs/list` for the path answers folder, file (`ENOTDIR`), missing (`ENOENT`) or unknown, parsed in the transport (`pathKind`). `destinationOf` is the whole policy as a table. A folder opens a folder shell. Anything else opens the Preview with the chat's id, because the Preview's read names the chat and so finds a sandbox file the listing can't see, and because its own errors already say what is wrong. A path written with a slash at its end is a folder on the writer's word, and opens with no request. The newest click wins, and the link shows `aria-busy` until it has opened.
- **A folder gets a shell of its own, and nothing is ever typed into a shell.** The Terminal tab's shells are one value (`terminal.ts` `Shells`) with pure steps. The server's shell and this computer's are always there. A folder shell is added per folder, so the same folder again shows the same shell, and starts it again only if it ended. The tab holds eight, and a ninth is refused with a note: nothing running is closed to make room. Each is a chip after the two computer buttons, with a close button that ends its ssh.
- **The folder reaches the server as one quoted word, or not at all.** `ssh_guard::Folder` is the one maker (ADR 0151). It takes `/…` or `~/…` up to 4096 bytes and refuses `'`, `\`, `!` and control characters. ssh then runs `cd '<folder>'; exec "$SHELL" -l` after the target, with `~/x` sent as `~/'x'`, and with `-o RemoteCommand=none` so a `RemoteCommand` in the owner's config doesn't make ssh refuse the command. A refused folder fails to start, and its folder shell says why. On this computer the folder is the process's working folder, which no shell parses.
- **The path menu** opens on a right click, the Menu key or Shift+F10: Open in the Preview, Open in the Terminal and Copy path. The Preview item reads the path as a file without asking what it is. The Terminal item opens a folder shell in a folder, in the folder a file is in, and says so when nothing is there. A path link is in the Tab order, and Enter opens it. Its tooltip starts with the full path.

## Considered options

- **Type `cd` into the running shell.** It is the smallest change. The app can't know what is in front (vim reads `cd…` as change and delete, a password prompt takes it as the password), no quoting is right for a shell the app can't identify, and model text typed into the owner's shell breaks the Terminal's rule.
- **One server shell, and ask before replacing it.** After the first folder a shell is always running, so every later click would be a question about ending it.
- **Link only paths that exist, by asking the server while rendering.** No dead links, but rendering would need the network, a reply could make the server touch a path with no click, and a streamed reply would no longer match the one-piece render.
- **A `hermes-path:` scheme and a custom URL transform.** Every link's safety policy would then pass through this app's transform, and a path would sit in `href`, where one missed `preventDefault` navigates the window.
- **Open the Preview first and turn to the Terminal on "Path points to a directory".** No extra request for a file, but the file-or-folder decision would live in two places, with a Preview history entry to undo.

## Consequences

- A click on a path that isn't written as a folder costs one dashboard request before anything opens.
- Some links lead nowhere: `/api/users` in a reply opens the Preview's "There's no file at this path on the Hermes server."
- A relative folder in running text needs a slash at its end or `./` in front to link. `src/ui` links in a code span or as a Markdown link.
- A folder with `'`, `\`, `!` or a control character in its path gets no shell on the server.
- Each folder shell is one more ssh until its chip is closed.
- A chat in a Docker sandbox names container paths such as `/workspace/x`. The Preview reads them through the chat, but a folder shell is on the host, where `cd` fails, says why, and leaves the shell in the home folder.
- A profile whose tools run on a second machine has its files there, while a folder shell goes to the Terminal's SSH target.
- `cd` into a folder a reply named runs whatever the owner's prompt runs there, such as a Git prompt or direnv. That machine already runs Hermes's commands as the same user.
- An ignored Rust test (`terminal.rs`, `a_folder_named_with_shell_syntax_…`) runs the folder command through every shell installed, as sshd does, with folder names such as `$(touch pwned)`. `HERMES_TEST_SHELLS` adds shells by full path.
- Paths in fenced code blocks don't link, and a tool call's path chips open the Preview directly, as before.
