# Artifacts are Outputs edited beside the chat, with Hermes's edits reviewed as patches

> **Partly superseded by [ADR 0164](0164-the-outputs-screen-is-removed-and-artifacts-open-from-the-preview.md)** (#570). An Artifact opens from Edit in the Preview's toolbar on a Server file, not from Outputs, and there is no "Unsaved edit" mark in a list: Edit on the same file brings the draft back. The rest of this ADR stands.

Issue #80 asks to work on a generated document beside the chat and to ask Hermes for targeted edits without the whole file being replaced by accident. An Output (ADR 0016) that is a text file can now be opened to edit in the preview pane beside the chat. That open file is an **Artifact**. This first stage covers Markdown and plain text, code included, since it's plain text too. Rich editors (spreadsheets, slides, collaborative editing) need designs of their own.

## Decisions

- **Which file, on which machine.** An Artifact is one path on one machine, opened in one connection and profile. Its identity is that scope, the machine, and the path (`artifactKey`). An Output is where its tool wrote it (ADR 0016):
  - A `host` Output (audio and images Hermes saves itself, or a file on the dashboard's machine) is read and saved through the managed-files routes, exactly as Server files edits a file (ADR 0024).
  - Every other Output is where the profile's tools run, which may be its SSH workspace. It is read with `GET /api/fs/read-data-url?path=&profile=` (the exact bytes, up to 16 MB) and saved with `POST /api/fs/write-text?profile=` with `{path, content}`. Hermes stages the text beside the file and renames it into place (`fs_write_text` at `bf0203a`).
  Every request names the Artifact's profile, so a file opened in one profile is never read or saved through another. ADR 0024 rejected `write-text` for Server files because it follows the profile's SSH workspace, so it may write a different machine from the one the screen lists. For an Output that is the point: it is the machine the tool wrote on, and the one the preview pane reads.
- **The write route is narrow.** The Rust relay still refuses every write to `api/files` and `api/fs` (ADR 0012). Saves go through one command, `fs_save_text` (`Dashboard::write_agent_text`). It sends only a full path (`/…` or `~/…`) with no `..` and no trailing `/`. It never writes a credential file (`protected_server_path`), because Hermes doesn't guard this route. It sends at most 8 MiB, Hermes's own limit. It is a transfer, so Cancel stops it, and a closed or replaced connection never sends it.
- **Same save rules as Server files.** The open, checked-save and copy logic is ADR 0024's, now shared (`remoteFiles.ts` `textEditing`) and given each machine's reads and writes. The editor opens only UTF-8 text up to 1 MiB with one kind of line end, and keeps CRLF and a byte order mark. The revision is the SHA-256 of the bytes read. Review changes → Save reads the file again and writes nothing if the revision changed. Afterwards it reads the file back and says "saved" only when the bytes match. A lost answer is settled by that read-back. For `write-text`, an answer counts as a refusal that changed nothing only if Hermes gives it before writing: 400 for a bad path, a folder or a missing parent; 403 not writable; 404 not found; 413 too large; 422; 503 `SSH workspace is unavailable`; or 500 `Could not write file`, since Hermes removes its temp file. Anything else is settled by reading the file back.
- **The draft is never the file.** The editor's text lives only in this app's memory (`ArtifactStore`), and nothing reaches the server until Save. Closing the pane, opening a chat, switching profile or going to another screen keeps the draft. Outputs marks the file "Unsaved edit", and Edit brings it back with its history. Only Cancel (which asks first when there are changes), signing out or closing the window drops it. Signing out and closing the window ask first while any Artifact has unsaved changes. The pane is keyed by what it shows, and it unmounts while hidden in a narrow window, so the editor holds nothing of its own that matters.
- **Asking Hermes is a proposal, not a write.** "Ask Hermes to edit" sends the selection to legacy `llm.oneshot {profile, instructions, input, max_tokens, temperature, session_id?}`. Hermes answers with text from a stateless model call (`run_oneshot` at `bf0203a`). It has no tools, so it can't touch the file, and it adds nothing to any chat. With nothing selected, the whole file is the selection, and the editor says so.
  - **What it's given:** the request, the document's path and revision, the selection between `<selection>` tags, and up to 24,000 characters of text on each side as quoted data. It's told to answer with only the new text for the selection and to treat the document as data, not instructions. A selection may be up to 60,000 characters.
  - **Which model:** when the chat that made the file is open in this app, its runtime session (`session_id`) lends that chat's model. Otherwise Hermes uses the profile's Text generation model, as Regenerate title does, and the proposal says which one answered.
  - **The patch:** the answer replaces exactly the selected range of the text the editor held when the owner asked. Text outside the selection is kept byte for byte, so a wider change happens only when the owner selects more or nothing.
  - **Review:** the proposal shows as a diff against that exact text, named by its base version. **Apply to the editor** works only while the editor still holds exactly that text on exactly that base version. If the owner typed, saved, merged, reloaded or restored meanwhile, it is rejected, never fitted onto the newer text, and **Ask again** asks against the text as it is now. Applying it is one undo step, and nothing is saved until Save.
- **Undo and redo** are the app's own, since the textarea's native undo breaks once React sets its text. Ctrl+Z, Ctrl+Shift+Z, Ctrl+Y, the webview's own Undo, and the buttons all use one history. A burst of typing is one step (a pause of one second starts another). An applied Hermes edit, a restored version, a merge, or using the server's version is always its own step. The history keeps at most 200 steps and 32 M characters, and the oldest go first.
- **Versions.** For each Artifact the app keeps, in memory, the file as opened, what each save replaced and wrote, and the server's version found when a save is checked. Versions holds at most 20 per file and 16 M characters in all, and the oldest go first. Any two of them, the saved version or the edit can be compared as a line diff. **Restore** puts a version in the editor, and Save writes it, checked like any other save. So the version before a save stays recoverable until the app quits or the owner signs out.
- **When both edit.** If Hermes, or anything else, changed the file since the edit started, Save writes nothing. It shows what changed on the server and keeps both versions. **Merge** is ADR 0024's line-based three-way merge, with conflicting stretches between markers. **Use the server's version** keeps the edit one Undo away. **Save mine as a copy** writes it beside the file under the first free `name (n).ext`.
- **Sandboxing.** The Markdown preview renders the draft with the app's Markdown component, as replies and the preview pane do (ADR 0007): no raw HTML, no scripts. Nothing in an Artifact runs, and nothing it holds reaches the app's credentials, which stay in Rust.

## Considered options

- **Save every Output through the managed-files upload, as Server files does.** Rejected: those routes are the dashboard's machine. For a profile with an SSH terminal, that isn't where `write_file` wrote. The file may not be there, or a different file may be.
- **Send the request into the chat as a message.** Rejected: the agent has its tools there and could rewrite the file itself, before any review. It would also add the request and the document to the chat's history.
- **Let Hermes return the whole file, or a diff to apply loosely.** Rejected: a whole-file answer can change text outside the selection without anyone noticing, and a loose patch can land somewhere other than the owner meant. A replacement for one exact range of one exact text can do neither.
- **Fit a proposal onto newer text** (rebase it when only other lines changed). Rejected for now: the issue asks for patches whose base no longer matches to be rejected, and Ask again is cheap.
- **Keep drafts and versions on this computer, as Persona does.** Rejected for now. As in ADR 0024 and ADR 0016, the app doesn't keep copies of the server's files in unencrypted webview storage. Versions on the server would need Hermes to keep them (below).

## Consequences and gaps

- **The check-then-write gap.** It is ADR 0024's: Hermes has no conditional write, so a change that lands between the revision check and the write is replaced. The read-back then finds our text. The fix belongs in Hermes: `write-text` taking an `expected_sha256` checked just before `os.replace`.
- **A copy can replace a file.** `write-text` has no "don't replace" mode, so Save mine as a copy relies on the name being free when the folder was listed a moment before. Backend fix: an `exclusive` flag that opens the target with `O_EXCL`.
- **Permissions.** A save writes a new file, so its permissions aren't kept, as with Server files. The review step says so.
- **Versions don't survive a restart.** A kept version lasts until the app quits or the owner signs out. Backend design: Hermes keeps each Output's versions itself (path, SHA-256, bytes, the tool call or client save that wrote it), which would also let Outputs tell versions apart by content (ADR 0016, "Capability gap").
- **Asking needs a model Hermes can reach.** `llm.oneshot` gives up after 60 s on the server, and the app after 90 s. If the chat isn't open, the Text generation model answers, which may be a small model. A missing sign-in for its provider reads as it does for Regenerate title. Hermes takes off one code fence around the whole answer, so a selection that is itself one fenced block comes back without its fence. The diff shows it.
- **Older servers.** A server without `/api/fs/read-data-url` or `/api/fs/write-text` can't open or save an Output where tools run, and the editor says what the server answered. One without `llm.oneshot` can't propose edits, but manual editing still works.
